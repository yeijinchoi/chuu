# 문구 편집기

게임의 **모든 글**(손님 대사·재방문 대사·반응·속마음·선택 대화·연락처·수칙·문자 템플릿·상품·UI 문구·엔딩·단서 …)을 낱개 1:1로 고치는 웹 도구다. 약 1,200개.

- 주소: 배포 사이트의 `editor.html` (예: `https://jeanychoi.com/chuu/editor.html`). 로컬은 `npm run dev` 후 `/editor.html`.
- 왼쪽 묶음(손님별 · 수칙·연락처·문자·상품 · UI·시스템 문구)을 고르거나 위에서 검색한다. 칸마다 한국어 이름과 경로 id(`customers/hanyeoreum/lines/opening`)가 붙는다.
- 고치면 즉시 이 브라우저에 자동 저장된다(다른 기기·브라우저로는 가지 않는다). 상단에 "저장됨 시각"이 보이고, 저장이 막히면 빨간 경고가 뜬다.
- 수정한 칸은 금색 줄로 표시되고 "원문으로"로 되돌릴 수 있다. `{name}` 같은 자리표시자가 빠지거나 지문의 `> `가 없어지면 경고한다.

## 결과를 게임에 반영하는 법
1. **게임에 반영(게시)** — 개발자용 기본 방법. 상단의 금색 버튼을 누르면 수정한 글이 **저장소의 `src/data/*.json`에 한 커밋으로 올라가고**, Pages 배포가 다시 돌아 1~2분 뒤 게임을 여는 모두에게 바뀐 글이 보인다.
   - 처음에 한 번 GitHub **개인 액세스 토큰**이 필요하다(대화상자의 "토큰은 어떻게 만드나요?" 참고): Fine-grained token, Repository access에서 이 저장소만 선택, Permissions 칸의 **+ Add permissions → Contents → Read and write**(Metadata: Read-only는 자동으로 붙는다). 토큰은 내 브라우저에서 GitHub로만 간다. "기억하기"를 켜면 이 브라우저에 저장한다(내 컴퓨터에서만).
   - 저장소(`소유자/이름`)와 브랜치를 확인한다. **이 브랜치가 배포되는 브랜치**여야 게임에 반영된다(현재 `master`와 `claude/trusting-faraday-4mk8i9`가 푸시 때 배포된다).
   - 저장소의 그 글이 편집기가 아는 원문과 달라졌으면(다른 곳에서 먼저 고쳤으면) 덮어쓰지 않고 그 칸만 건너뛴다고 알려 준다. 그 사이 다른 커밋이 올라가 충돌하면 "다시 게시해 주세요"가 뜬다.
   - 게시가 끝난 뒤 배포가 반영되고 편집기를 새로고침하면, 이미 반영된 수정은 목록에서 자동으로 정리된다.
2. **미리보기**: 게시 전에 "게임에서 미리보기"로 새 탭의 게임에서 먼저 확인한다(`?edited=1`, 왼쪽 아래에 표시). 저장본은 바뀌지 않는다.
3. **패치로 전달**: "패치 복사/내려받기"로 얻은 패치를 개발 세션에 전달해도 된다. 직접 적용하려면:
   ```bash
   npx vite-node tools/apply_text_patch.ts 패치.json --dry   # 시험
   npx vite-node tools/apply_text_patch.ts 패치.json         # 적용
   ```
   또는 "수정된 JSON 내려받기"로 받은 파일을 `src/data/`에 덮어쓴다. "불러오기"로 패치를 다시 올려 이어서 고칠 수도 있다.

## 알아 둘 것
- 손님 **이름**을 바꾸면 `contacts.json`(연락처 이름)·엔딩 문구 속 이름은 따로 고쳐야 한다.
- 대사 앞의 `> `는 지문(장면 묘사) 표시다. 지우면 대사로 나온다.
- 편집 대상에서 뺀 값: id, 카테고리·색, 인사 선호, 스프라이트, 수칙 번호·판정 필드, 수치(예산·시각), 단서·플래그 id.
- 구현: `src/editor/textmap.ts`(낱개 추출·경로·패치, DOM 없음), `github.ts`(게시: git 데이터 API로 한 커밋), `store.ts`(저장·게임 데이터 연결), `main.ts`(화면). 테스트 `tests/core/textmap.test.ts`, `tests/core/publish.test.ts`(가짜 GitHub).
